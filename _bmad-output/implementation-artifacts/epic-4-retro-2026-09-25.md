### Pattern divergence

**F-2 — `DownstreamColumnPrecisions` has no schema parity lock.** `1ab5ea7` adds
`Persistence/DownstreamColumnPrecisions.cs` (23 hand-transcribed `(precision, scale)` entries), applied
via `HasPrecision` (`AscoLsiDbContext.cs:176-185`). Its two siblings from the same schema are each
parity-locked against `scripts/schema/01-ascolsi-tables.sql` (`DownstreamColumnLengthsParityTests`,
`DownstreamColumnMagnitudesParityTests`); `grep -rl DownstreamColumnPrecisions tests/` → no test source.
Checked manually this session: the 23 entries match the 27 `DECIMAL(p,s)` lines of the schema
(`01-ascolsi-tables.sql:161-378`, 4 names repeated at identical precision). Correct today; a future
edit is caught only by the Integration production-parity tier, which needs the production instance
(`1ab5ea7` message: the rounding bug went unseen until that tier was fixed). `DownstreamColumnMagnitudes`
(10^(p−s)) is also derivable from this map, so the parity test can cover both.
Disposition: **fix now** (cheap Unit-tier test).
